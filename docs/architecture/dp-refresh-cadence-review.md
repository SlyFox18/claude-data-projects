# DP Refresh Cadence Review

Generated by `tools/dp-migration/cadence_review.py` (2026-09-29).

This table exists so Brian can set each producer's refresh cadence deliberately instead of everything defaulting to daily. For every item in `deploy/dp_refresh_dag.json` it shows what the item currently reads and produces, how often it's actually run in the last 60 days, how many other items and reports sit downstream of it, and whether the old `dp_backend_scope.json` ever assigned it a cadence at all (45 of the 98 notebooks never were in that file and simply defaulted to daily when this config was bootstrapped).

**How to read it:** `Reads` lists DP-produced tables this item depends on (resolved from its `dependsOn`) plus external/Bronze source tables found by re-scanning the notebook code -- external reads are marked with `*`. `Static?` is `Yes` only when the notebook has no real table reads at all (e.g. a fixed calendar); a notebook that reads only a `Files/` CSV is called out separately rather than marked static, since the CSV's contents can still change. `Median run (s)` / `Runs seen` come from Completed job instances in the Fabric job history over the last 60 days -- `—` means no completed runs were found in that window. `Downstream items` is the count of other items whose dependency chain includes this one. `Reports` lists report models that read a table this item produces directly (not transitively). The scanner's read-detection is regex-based and a few noise words can slip through as spurious external reads; treat `Reads` as a strong hint, not ground truth -- see the caveats at the bottom.
