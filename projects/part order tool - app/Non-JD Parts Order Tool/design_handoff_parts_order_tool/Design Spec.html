4 · The big fix — navigation

The current app relies on Back buttons, which is the main thing making it feel hard to move through. Replace that with a persistent left navigation rail plus a breadcrumb at the top.

  • Left rail (dark, 248 wide): Home · Recommended Reorder · One-Time Order · Part Lookup · Transfers, with App Settings + user pinned to the bottom. Build it as a vertical container of buttons (or a Gallery) placed on every screen — or once in a component.
  • Active state: highlighted row using the nav-active fill, plus a 3.5px accent bar on the left edge. Track the current screen in a variable (e.g. Set(gblNav,"reorder")) and color each item with If(gblNav="reorder", …).
  • Breadcrumb top-left replaces "Back": e.g. Part Lookup › 859090. Each crumb is a button that Navigate()s back up the chain — no more dead-end Back buttons.
  • Part Information becomes one screen with inline tabs (Detail · History · Settings) instead of separate top buttons.
  • One-Time Order becomes a 2-step wizard with a step indicator (Set up → Review), so users always know where they are.
  • Transfers gets a permanent home in the rail now (shown as "Soon") so it's ready when you wire it up as the first step of the flow.

5 · Component recipes

Primary button

Fill = accent · Color = White · BorderRadius = 9 · Height = 38 · Font = Lato Semibold 14 · horizontal padding 16. Secondary: Fill White, Color = text primary, 1px border in border color. Success (Export): Fill #1A7D43.

Status pill

Label inside a container · BorderRadius 999 · Height 24 · padding 0 10 · Fill = soft status color · Color = solid status color · Font Lato Bold 12.

Data table (Gallery)

TemplateSize 56 · 1px bottom separator in border color · hover fill = app background. Right-align all numbers. Color the On Hand value by status (red at 0, amber below target). Add a Status pill column and a Need column (= Target − OnHand − OnOrder) so the action is obvious at a glance.

Selection action bar

A card pinned under the gallery showing "N parts selected · Est. $X" with the primary "Create Order" button. Keep the running total live so users feel in control.

6 · Notes that matter for your data

  • Result limits / delegation: the redesign keeps Branch + Franchise as the primary filters at the top of every list — push those filters to the Lakehouse/SharePoint query so you stay under the row cap and never load more than one branch's parts at once.
  • "Reorder needed only" toggle should filter server-side where possible, not just hide rows client-side.
  • SharePoint settings map cleanly to the new App Settings screen (pipeline run time, defaults, pre-approved rules) — one place instead of buried per-part.
  • Per-part overrides stay on the part's Settings tab, with the "applies to tomorrow's run" note kept visible.
