# 0.12.0 try-it: Inventory reports (mock mode)

For Brian, before deploying 0.12.0. **Inventory** is a new area: the Corp Parts workbooks as reports over every
active JD part, starting with **MLPF Gaps**. The built-in uses exactly the workbook's rules and columns, so it lists
the same parts as MLPF Gaps.xlsx on the same morning. **Copy as my own** makes an editable version, such as "2 or 3
demands", without changing the built-in.

**Start:** in PowerShell, `cd C:\Users\bfox\Documents\Git-Projects\nonjd-order-app`, then `npm run dev`, and open the
address it prints. Mock mode uses made-up data and never writes to SharePoint; a page refresh starts the mock over.
The mock has a handful of JD parts at branches 1, 2 and 12, a saved copy **MLPF Gaps – 2 or 3 demands** (by "Ben
Hill") and an archived "Old SLC test".

## 1. Open MLPF Gaps

Open **Inventory** from the launch page (in the left menu it's **Reports**). The list shows **MLPF Gaps** (🔒 Built
in) with 1 part and Ben's copy with 2. Open **MLPF Gaps**: it finds one part, **JD-MLPF-OK** at branch 1. The other
test parts each break one rule (3 demands, 1 on hand, on order, package of 2, not returnable, source AN, SLC 21…,
superseded, branch 12), so none of them show. Try the branch filter, the search box and a column heading. Click the
part number to see every field for the part; Escape closes it. **Export CSV** and open the file: the headings are the
workbook's (Branch, PartNumber, … DealerGroupCode, OnOrder, OnHandQty, Demands), so it lines up beside MLPF Gaps.xlsx.

*Look for:* whether the page reads like the workbook to Ben, and whether "Total cost (1 each)" is a useful total.

## 2. Make your own version

On MLPF Gaps click **Copy as my own**. The editor opens with the nine MLPF conditions and the name "Copy of MLPF
Gaps". Change **Corp demands** **=** **2** to **≥** **2**. The **Try it** card now finds 2 parts (JD-MLPF-OK and
JD-MLPF-DEM3). Rename it, then **Save report**: it opens with "Report saved." and its own two parts. Its table and
CSV add the columns its conditions use beyond the workbook's (here Package qty, Return indicator, Super To).
**Edit** brings you back; saving again says "Report updated.".

*Look for:* whether the conditions read clearly ("SLC doesn't start with 21, 90, 91, 99"), and whether any JD field
you'd expect is missing from the field list.

## 3. Tidy the list

On the Inventory list, **Switch off** your copy: it stays, marked **Off**. **Archive** it: it leaves the list; **Show
archived** brings it back with **Unarchive**. The built-in can't be switched off, archived or edited, only copied.

**Then:** App Settings → About should say **Version 0.12.0**. In the real app, until the first v6 publish runs,
Inventory says "JD parts aren't in today's data yet"; that's expected for the first morning. The real MLPF Gaps
should show about 10,000 parts and take a few seconds to load the first time (27 branches of JD parts).
